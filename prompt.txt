SYNC ARCHITECTURE

Implement an append-only event synchronization design suitable for multiple offline devices.

Each event must have:

- event_id UUID
- entity_id UUID
- device_id UUID
- event_type
- schema_version
- payload
- client_created_at
- effective_at
- server sequence assigned by PostgreSQL
- authenticated user and bakery derived by the server

Implement idempotent push and cursor-based pull.

Prefer Supabase PostgreSQL RPC functions for atomic push and pull operations. Use an Edge Function only if database RPC cannot safely provide the required authentication, validation, or response behavior.

Push behavior:

- Send small batches
- Validate each event
- Derive auth user and bakery on the server
- Check role permissions
- Deduplicate by event_id
- Process accepted events transactionally
- Return an acknowledgment for each event
- Preserve rejected events locally
- Never remove a pending event merely because an upload was attempted

Pull behavior:

- Pull events after a stable server sequence cursor
- Sort by server sequence
- Paginate
- Return the next safe cursor
- Make retries safe
- Atomically apply pulled events and advance the local cursor

Do not use client timestamps as the event cursor.

Do not use last-write-wins for financial and inventory facts.

Trigger synchronization:

- At application startup
- On resume
- When connectivity returns
- Periodically while open
- When the user presses Sync

Use bounded exponential backoff.
